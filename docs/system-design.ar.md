# تصميم النظام — ميديا تولز

كيف يعمل النظام: تدفّق البيانات، والثوابت التي يحافظ عليها، وأنماط الفشل
المصمَّم ليصمد أمامها. هذه الوثيقة تقرأها حين تحتاج أن تغيّر شيئًا وتريد أن
تعرف ما الذي تكسره.

**[English](system-design.md) | العربية**

---

## ١. أي نوع من الأنظمة هذا

تطبيق صفحة واحدة، بلا خلفية خادمية، بلا خطوة بناء، وبلا أي حركة شبكة. كامل
حالة النظام تعيش في إغلاق وحدة JavaScript واحدة إلى جانب الـ DOM. لا قاعدة
بيانات، ولا جلسة، ولا حالة على الخادم.

لهذا نتيجة واحدة كبيرة: **معظم أخطاء هذا التطبيق أخطاء تزامن** — النموذج
وـ DOM والبيانات المحفوظة يختلفان فيما بينها. لذلك بُنيت البنية حول إبقاء
ثلاثة أشياء متّفقًا عليها:

```
items[]   +   index        النموذج: ما المُحمَّل، وأيّهما
    │
    │  render() / renderList() / refreshRow()
    ▼
الـ DOM                    ما يراه المستخدم
    │
    │  save()، مؤجَّل ٤٠٠ جزء من الثانية
    ▼
localStorage               ما يبقى بعد إعادة التحميل
```

كل تغيير في النموذج يجب أن يحدّث الثلاثة جميعًا أو لا شيء. معظم عيوب هذا
المشروع كان هناك عنصر رابع — عنصر الوسائط — يشارك دون أن يحسبه أحد.

## ٢. الوحدات وعقودها

| الوحدة | ما تملكه | ما لا تعرف عنه |
|---|---|---|
| `index.html` | الترميز، وسهم أيقونات SVG المضمّن | أي سلوك JavaScript |
| `app.js` | كل حالة التطبيق | وجود مكتبة تشغيل |
| `js/media.js` | التشغيل: تحميل، تشغيل، بحث، ملء شاشة | القائمة، والواجهة |
| `js/source.js` | عقد المحوّل، مُتحقَّق منه عند التحميل | أي محوّل هو النشِط |
| `js/source-web.js` | `File` → رابط كائن، MIME، التفضيلات | الـ DOM عداهى المُدخل المخفي |
| `js/i18n.js` | النصوص، الأرقام، الصيغ، الاتجاه | معنى أي شيء |
| `js/settings.js` | اللغة، الشعار، لون الهوية | بقية الإعدادات |
| `serve.js` | ملفات ساكنة على الواجهة المحلية | أي مفهوم في التطبيق |

`app.js` ينادي أربعة كائنات عالمية فقط: `MediaFileSource` و`MediaBridge` و`I18n`
و`MediaSettings`. كل منها واجهة موثّقة لا تفصيل تنفيذ. هذه الخاصية هي ما يجعل
الشيفرة صغيرة بما يكفي ليست كبيرة بما يكفي لتُحفظ في الذاكرة في الذاكرة.

`serve.js` خارج المخطط عمدًا. ليس جزءًا من التطبيق، بل طريقة لوضع التطبيق على
منفذ.

## ٣. التجريد المركزي: عنصر الوسائط

```js
{
  name:   'holiday.mp4',      // للعرض
  mime:   'video/mp4',        // إلزامي: المشغّل يختار المزوّد منه
  kind:   'video' | 'audio' | 'image' | null,
  path:   null,               // مصدر سطح المكتب يملؤه
  file:   File,               // مقبض محوّل المتصفح
  url:    'blob:...',         // يُنشأ كسولًا، ويُحرَّر صراحةً
  duration:   3725.4,         // بالثواني، أو null حتى الفحص
  thumb:  'data:image/...',   // مصغَّر، لا الأصل أبدًا
  position:  124.3,           // موضع الاستئناف، بالثواني
  openEnded: false            // المدة أُبلغت عنها كـ Infinity
}
```

ثلاث خصائص في هذا الشكل承载 الثقل، وكل واحدة كلّفت عيبًا:

- **`mime` إلزامي.** رابط `blob:` لا امتداد له يستنتج منه المشغّل مزوّدًا.
  سيفشل كل تحميل دون أي  مؤشّر للسبب.
- **`kind` قد يكون `null`**، أي «غير قابل للتشغيل هنا». تُصفّى القيم الفارغة
  عند الباب وتُ**عدّ**، فإفلات ملفات مختلطة يخبر المستخدم كم منها رُفض بدل أن
  يبدو مُتجاهَلًا.
- **`file` و`url` لهما مالكان مختلفان.** الـ `File` للتطبيق، والـ `url`
  للمحوّل ويجب إعادة تسليمه. `release()` يسلّم الرابط فقط ويحتفظ بالـ
  `File`، وهذا ما يجعل التراجع عن المسح ممكنًا ويمنع تحوّل العنصر المُحرَّر
  إلى غير قابل للاستخدام إلى الأبد.

## ٤. تسلسل التحميل

هذا أدقّ جزء في النظام، لأن عنصر الوسائط غير متزامن والتطبيق متزامن.

**المشكلة.** `load(item)` تفعل أربعة أشياء يجب اقترانها بأحداث تصل لاحقًا،
ربما بعد استبدال العنصر:

1. بحث الاستئناف، ليُطبَّق على `loaded-metadata`
2. طلب التشغيل التلقائي، ليُعاد على `can-play`
3. تحديثات الوقت، ويجب نسبتها إلى العنصر الصحيح
4. الأخطاء، ويجب التخطّي مرة واحدة بالضبط

**الآلية.** كل تحميل يأخذ تذكرة (`currentLoad = ++loadSeq`). المعالجات التي قد
تنتمي إلى تحميل مستبدَل تُثبَّت **لكل تحميل** وتُغلق حول تذكرتها الخاصة، فتعرف
أنها قديمة:

```js
function onSuperseded(events, handler) {
  const seq = currentLoad;
  const wrapped = (e) => {
    if (seq !== currentLoad) return;   // مزوّد مستبدَل: لا تفعل شيئًا
    dropLive();
    handler(e);
  };
  ...
}
```

المعالجات تُثبَّت لكل تحميل لا مرة واحدة في `init()` لسبب محدّد: أحداث الوسائط
لا تحمل هوية خاصة بها، فمستمع مسجَّل مرة واحدة لا يستطيع معرفة **أي** تحميل
ينتمي إليه الحدث. (محاولة سابقة قارنت `currentLoad` بنفسه وقت الحدث؛ لم تكن
تستطيع أن تعمل أبدًا، وقد شُحنت في.commit قبل أن يلتقطها اختبار المتصفح.)

**ثلاث قواعد تسلسل إضافية، كل واحدة تُصلح عيبًا مختلفًا:**

- **تُحجب تحديثات الوقت ما دام لا مصدر جاهز.** الإيقاف أثناء التفكيك يُتبع
  بـ `time-update` يحمل وقت المقطع **الخارج**. مؤشر التطبيق انتقل بالفعل، فتسجيله
  كان يعطي المقطع التالي موضع استئناف للمقطع السابق.
- **يُسقط المصدر السابق قبل ربط مصدر جديد.** سحب رابط كائن ما زال العنصر
  يشير إليه هو استخدام بعد تحرّر للمورد بالمنطق، ولا يبدو أنه يعمل إلا لأن
  التعيين التالي يقطع الجلب الجاري — وهو تفصيل تنفيذ لا ضمان.
- **يُهمَل بحث قديم.** تُصفَّر `pendingSeek` عند المسح وعند كل تحميل جديد،
  فلا يترك تحميل فاشل موضعًا خلفه.

## ٥. الفحص

المدة والمصغّرة تُقرآن من عنصر منفصل، على التوازي، بثلاثة عمّال:

```
إفلات ٢٥٠ ملفًا
   → probeAll: ثلاثة عمّال
      → probe(item): <video> منفصل، مكتوم، preload=metadata
         → await loadedmetadata (مهلة ٢٫٥ ثانية)
         → بحث إلى ٠٫١ ثانية، await seeked (مهلة ٢ ثانية)
         → canvas → صورة JPEG بعرض ١٦٠ بكسل
      → refreshRow(item): يحدّث ذلك الصف فقط
```

ثلاثة قرارات هنا كلها لجعل التطبيق لا يبدو معطّلًا:

- **عنصر منفصل، لا المشغّل أبدًا.** الفحص يجب ألا يزعج التشغيل.
- **مهل قصيرة.** ملف لا يُبلّغ عن مدته يجب ألا يحتجز عاملًا طويلًا: بثلاثة
  عمّال، بضع مئات من الملفات غير القابلة للقراءة كانت ستضع الطابور دقائق
  متأخرًا دون أي indication على الشاشة.
- **صف واحد يُحدَّث، لا إعادة بناء القائمة.** كانت القائمة تُعاد بناؤها عند
  كل فحص — churn بمقدار O(n²) من العناصر، وكان أي سحب جارٍ يُدمَّر في منتصفه.
  الآن `refreshRow` يلمس صفًا واحدًا، ويُعلَّق الرسم تمامًا أثناء سحب صف.

**المصغّرات دائمًا مُصغَّرة.** حمل صف صورة مرة واحدة رابط `blob:` الخاص بالعنصر
نفسه، فجعلت قائمة صور كبيرة المتصفح يفكّ ترميز كل الأصل ليُرسم صف بعرض ١٦٠
بكسل.

## ٦. الحفظ

`localStorage`، مفتاح واحد (`mediatools.prefs`)، يُكتب بتأخير ٤٠٠ جزء من الثانية.

**ما يُكتب:** `index` و`position` و`fit` و`loop` و`volume` و`muted` و`ui`
و`list` و`autoplay` و`settings`.

**ما لا يُكتب عمدًا:** `items`. قائمة التشغيل تحمل روابط `blob:` تموت مع
المستند، فكتابتها تنتج صفوفًا لا يمكن تشغيلها. و`restore()` يرفض أيضًا إعادة
بناء قائمة ما لم يُعلن المصدر أنه يستطيع حلّها، حتى لا يُكسر هذا الربط بإضافة
كلمة واحدة إلى `PERSISTED`.

**قاعدتان تحفظان صدق البيانات:**

- **يُكتب الموضع من النموذج لا من العنصر.** `items[index].position` صحيح
  بالمنشأ، أما `media.currentTime` فما زال وقت المقطع الخارج أثناء التبديل.
- **الفشل في الكتابة يُبلَّغ ولا يُبتلع.** شعار بصيغة base64 قد يتجاوز الحصة،
  و`catch {}` عارية هناك تفقد اللغة واللون والصوت والموضع دون أي indication.
  صارت تُطلق حدثًا، وحوار الإعدادات يقول ذلك، والصور الكبيرة تُصغَّر قبل
  تخزينها قلّ احتمال حدوثه أصلًا.

## ٧. نموذج الفشل

| الفشل | ما يراه المستخدم | لماذا ليس أسوأ |
|---|---|---|
| ملف لا يُفكّ ترميزه | «لا يمكن تشغيل هذا الملف» | تخطٍّ واحد لكل مقطع، لا حلقة |
| تشغيل تلقائي مرفوض | «اضغط تشغيل للبدء» | الأيقونة تعكس الواقع لا النيّة |
| إفلات ملفات غير قابلة | «N ملف لا يمكن تشغيله هنا» | لا شيء يُهمَل بصمت |
| صورة تالفة | الرسالة نفسها | للـ `<img>` مسار خطأ، ولم يكن له |
| المساحة ممتلئة | تنبيه في الإعدادات | يستمرّ التطبيق، في الذاكرة |
| طلب خادم مشوَّه | `400` | الخادم لا يموت |
| حدث مفتاح بلا `key` | لا شيء | مُعالَج، وكان يرمي |
| `scrollIntoView` غير موجودة | لا شيء | محميّ، وكان يُجهض طابور الفحص |

القاعدة في كل ذلك: **فشل لا يراه المستخدم لا يمكن تمييزه عن تعليق التطبيق.**
كل واحد من هذه يُنتج رسالة أو يتدهور بصمت لكن بضرر معدوم. ولا واحد منها يترك
الواجهة تكذب عن الحالة.

للرسائل عمران، لأن المعنى مختلف. «اضغط تشغيل للبدء» يصف الحاضر فيُسحب حين
تبدأ الوسائط؛ و«٣ ملفات لا يمكن تشغيلها» يصف الماضي فينتهي_timeout.

## ٨. الإدخال ولوحة المفاتيح

معالج عام واحد، مُسجَّل في طور **الالتقاط**.، وهذا ليس اختيارًا أسلوبيًا: أزرار
المكتبة تنادي `stopPropagation()` عند `keydown`، فلا يرى مستمع فقاعي المفتاح
إطلاقًا بعد أن يأخذ أي عنصر تحكّم التركيز. لهذا بدا `l` و`c` معطّلَين.

طور الالتقاط يعني أن المعالج يعمل أولًا، فيجب أن يتنازل بوضوح:

1. المفاتيح المعدَّلة (`ctrl`/`meta`/`alt`) — اختصارات المتصفح تعمل
2. `Escape` — يغلق الطبقة العليا بالترتيب
3. حوار الإعدادات، وأي شيء داخل حقل نموذج — يملكان لوحة المفاتيح
4. أشرطة المكتبة، لمفاتيح الأسهم
5. صف قائمة مركَّز عليه، لـ Enter وSpace والأسهم — معالج الصف يملكها، وطور
   الالتقاط كان سيبتلعها قبله

لكل اختصار موثَّق اختبار يؤكّد **الأثر المحدد** للمفتاح، لا مجرد أن شيئًا
تغيّر — نسخة أولى من ذلك الاختبار نجحت بينما نصف الاختصارات لا تفعل شيئًا،
لأنه كان يقارن لقطةً لم يعبّر عنها أكثرها يتركها كما هي عمدًا.

## ٩. من اليمين إلى اليسار

`dir="rtl"` على المستند يعكس نموذج الصندوق، لكنه لا يعكس أي إحداثية مكتوبة
بيد صريحة، ولا نسبةً داخل `left`. كل واحد من هذه كان عيبًا حقيقيًا:

- لوحة قائمة التشغيل كانت مثبّتة بـ `left` فيزيائية
- علامة الصف النشط تستخدم `inset 2px 0 0` — حافة يسار فيزيائية
- تعبئة شريط التقدير وإبهامه مثبّتان بـ `left` ونسبة، فبالعربية تنمو التعبئة
  **بعيدًا** عن البداية
- مجموعة من الحشوات والمحاذاة، صارت كلها خصائص منطقية

الأرقام تتبع اللغة. العربية تثبّت `ar-u-nu-arab`، لأن `ar` المجرّدة تُحَلّ إلى
**نظام الأرقام اللاتيني** في CLDR الحالي — وهو ما ترك أرقامًا غربية داخل نص
عربي. وصيغ الجمع تأتي من `Intl.PluralRules`، مُطبَّقة على عدد مُعيد إلى أرقام
ASCII، لأن العدد يصل غالبًا مُنسَّقًا مسبقًا.

## ١٠. هيكل سطح المكتب: ما يتغيّر وما لا يتغيّر

بُنيت البنية لهذا، فالتغيير صغير:

- **أضِف `js/source-tauri.js`** يصدّر `window.MediaFileSourceTauri` مع
  `openFiles` و`urlFor` و`release` و`loadState` و`saveState` و`canPersist`،
  و`dropItems` حقيقي يغذّيه ملف أحداث الهيكل بدل `DragEvent` من الـ DOM.
  حمّله قبل `js/source.js` فيُختار تلقائيًا.
- **اجعل `canPersist()` يعيد `true`** وأضِف `items` إلى `PERSISTED`. عندئذٍ
  تبني `restore()` القائمة، لأن المسارات تُحلّ.
- **لا تغيّر شيئًا آخر.** `app.js` يقيّد الإدخال حتى يستقرّ الاستعادة، وينسّق
  إفلاتًا يصل مبكرًا، ويعامل `dropItems` كأنه قد يكون غير متزامن.

`js/source.js` يتحقّق من العقد عند التحميل، فمحوّل سطح مكتب فيه خطأ يفشل فورًا
وباسم الدالة، لا لاحقًا وفي مكان آخر.

## ١١. استراتيجية الاختبار

**الوحدة (`npm test`، jsdom).** يحمّل الترميز الحقيقي والسكربتات الحقيقية؛
ويقلّد مكتبة التشغيل وحدها. كل سلوك يُقاد عبر الـ DOM المشحون — نقرات وإفلات
 وضغطات مفاتيح — لأن اختبارًا ينادي دالة داخلية يثبت شيئًا لا يستطيعه المستخدم.

المقلِّد ليس stub. يُصدر وقت المقطع الخارج عند تفكيك المصدر، ويمكن أن يُمضى
بفشل تحميل أو رفض تشغيل. بدون هذه السلوكات الثلاثة، لم تكن الانحدارات التي
عانى منها هذا المشروع قابلة للاختبار في المجموعة السريعة.

**الفجوة التي تستحق التسمية.** jsdom لا يؤدّي تخطيطًا. لذلك الهندسة
والتكديس والفيضان والتباين وانعكاس الاتجاه لا تُفحص إلا في مجموعة المتصفح —
وهو بالضبط كيف نجا عيبا الرسالة المخفية وصيغ الجمع العربية اختبارَي الوحدة.
المجموعتان متكاملتان، والمجموعة الثانية هي المرجع في كل ما يمكن رؤيته.
