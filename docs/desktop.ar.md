# بناء سطح المكتب

التطبيق نفسه في نافذة أصلية. بدون خطوة بناء للنسخة المتصفّحية، وبدون خادم،
وبدون تثبيت لنسخة المتصفح — هيكل سطح المكتب هو ما تسلّمه لشخص.

**[English](desktop.md) | العربية**

---

## ١. ما هو

نافذة Tauri 2 حول التطبيق القائم. قائمة التشغيل، واللوحة، وأدوات النقل،
والإعدادات، والتعريب — كلها الشيفرة الموجودة أصلًا في هذا المستودع، دون
تغيير. يوفّر الهيكل الأشياء الثلاثة التي لا تستطيع علامة تبويب المتصفح تقديمها:

| | المتصفح | سطح المكتب |
|---|---|---|
| إضافة ملفات | `<input type=file>` | حوار ملفات النظام |
| مكان الملفات | رابط `blob:` يموت مع التبويب | مسار حقيقي |
| القائمة في التشغيل التالي | مستحيلة | تُكتب كمسارات |
| إفلات الملفات | حدث `DragEvent` بكائنات `File` | `tauri://drag-drop` بمسارات |
| التفضيلات | `localStorage` | ملف JSON في مجلد الإعدادات |

هذا هو الفرق كله. وما عداه هو التطبيق نفسه.

## ٢. التشغيل

```bash
npm install
npm run desktop:dev        # يبني ملفات الويب ثم يشغّل مع إعادة تحميل Rust
npm run desktop:build      # ينتج ملفات التثبيت
```

`npm run desktop:dev` يجمّع `dist/` أولًا. لا يرى المُجمِّع المستودع أبدًا:
`scripts/build-frontend.mjs` ينسخ قائمة صريحة من الملفات، فلا يمكن أن ينتهي
بـ `node_modules` أو الاختبارات أو التوثيق داخل بناء مُسلَّم، وملف تحتاجه الصفحة
لكن نسيته القائمة يُفشل البناء بدل أن يُشحن تطبيقًا ينقصه سكربت.

### المخرجات

| الهدف | المنصّة |
|---|---|
| `.deb` | لينكس |

## ٣. ما هو مُتحقَّق منه، وما ليس

الدقة هنا مهمة، لأن «يُبنى» ليست «يعمل»، والفرق مهم حين تسلّمه لشخص.

**مُتحقَّق منه بتشغيل الملف المبني هنا**

- الهيكل يُبنى ويُشغَّل
- النافذة تُفتح والصفحة تُركَّب
- `window.__TAURI__` قابل للوصول، ومعه `invoke` و`convertFileSrc` و`event.listen`
- `convertFileSrc` ينتج `asset://localhost/<المسار المرمَّز>` على لينكس
- `js/source-tauri.js` يُسجَّل و`js/source.js` يختاره — التشخيص يبلّغ
  `active_source: desktop`
- `MediaBridge` يُركَّب، فجانب التشغيل سليم

**مُتحقَّق منه بدون شاشة**

- `cargo test` — ٦ اختبارات لملف الحالة، والكتابة المرحَّلة، وترتيب قائمة
  المجلد، وفحص الوجود
- `npm test` — ٢٠ اختبارًا لمحوّل سطح المكتب مقابل هيكل وهمي: تحويل المسار
  إلى عنصر، ومسارات ويندوز، وتخزين رابط الأصل، و`release`، وملف مُنقل، ومجلد،
  والمفاتيح المحفوظة، وكتابة فاشلة، ودمج الإفلات

**غير مُتحقَّق منه، ويحتاج إنسانًا لديه شاشة**

- حوار الملفات والمجلدات nativoّ يفتح ويعيد نتيجة
- فيديو يعمل فعليًا
- ملف مفلوت يصل
- القائمة تنجو من إعادة التشغيل

لا توجد شاشة افتراضية على هذه الآلة ولا صلاحية لتثبيت واحدة، فبقيت هذه. أما
`cargo test` واختبارات الهيكل الوهمي فتغطّي المنطق على جانبي كل منها؛ وما لا
تغطّيه هو سطرا الوصل بينهما.

## ٤. مشكلة الترميز، وكيف تتحقّق منها

على لينكس يفكّ العرضُ ترميز الوسائط عبر GStreamer. والآلة التي تفتقر إلى
مُفكِّك MP4 تُظهر تطبيقًا يُحمَّل ويفتح ويرفض بصمت تشغيل أي شيء — لا خطأ ولا
رسالة، مجرد صورة لا تظهر.

هذه ليست فرضية: كانت صحيحة على الآلة التي بُني عليها هذا، ولهذا يوجد التشخيص.

```bash
./src-tauri/target/release/custom-media-player --diagnose
```

يطبع هل واجهة الهيكل قابلة للوصول وهل حُمِّل مقطع H.264 حقيقي، ويفتح نافذة
أثناء ذلك. وعلى آلة لا تستطيع تشغيل H.264 يقول ذلك صراحةً.

لإصلاح آلة لينكس عاجزة عن ذلك:

```
sudo pacman -S gst-plugins-good      # آرتشي / كايتشي أو إس: يوفّر مُفكِّك MP4
```

`gst-plugins-base` و`-bad` و`-ugly` تكون مثبَّتة عادةً. و`gst-plugins-good` هي
التي تحمل `isomp4` و`matroskademux` و`wavparse`، وغياب الثلاثة هو ما يجعل
MP4 يفشل بصمت.

ويندوز وماك يجعلان مرافقَي الوسائط فيهما جاهزَين مع الرموز، فلا ينطبق هذا الأمر عليهما.

## ٥. الملفات، وما يحدث حين يُحرَّك أحدها

التطبيق يشير إلى الملفات في مكانها. لا يُنسخ شيء، فلا تكرار في مساحة القرص ولا
مجلد مكتبة لإدارته.

المقابل أن القائمة تنجو من الملفات التي فيها، فيمكن لملف أن يُحرَّك أو تُغيَّر
تسميته أو يُحذف لاحقًا. عندها:

- الصف **يبقى**، باهتًا، مشطوبًا، وموسومًا `gone`
- لا يمكن تشغيله، واختياره يشرح السبب بدل أن يفشل بصمت
- ما زال قابلًا للحذف
- بقية القائمة لا تتأثر

قائمة تفقد المقاطع بصمت أسوأ من أخرى تُظهر ثقبًا بوضوح، فلا يُحذف شيء خلف ظهر
المستخدم أبدًا.

## ٦. بنية الملفات

```
src-tauri/
  Cargo.toml
  tauri.conf.json            النافذة، والأمان، وأهداف البناء
  capabilities/default.json   الصلاحيات التي يحتاجها التطبيق، لا أكثر
  src/
    main.rs                  ست أوامر، بلا أي منطق تشغيل
    tests.rs                 المنطق القابل للاختبار بدون شاشة
    diagnostic.js            ما يحقنه ‎--diagnose
    diagnostic-collect.js    كيف تُجمع النتيجة
  icons/                     مولَّدة بـ `npm run icon`
js/
  mime.js                    أي نوع ملف هذا، لكل المصادر
  source-web.js              محوّل المتصفح
  source-tauri.js            محوّل سطح المكتب
  source.js                  يختار واحدًا، ويتحقّق من العقد
scripts/
  build-frontend.mjs         يجمّع dist/ من قائمة صريحة
icon-source.png              الأيقونة التي يولّد منها `npm run icon`
```

### الوضع الأمني، بصراحة

- التطبيق **بلا أي قدرة شبكية**. لا عميل HTTP، ولا محتوى بعيد، ولا CSP يسمح
  إلا بأصل التطبيق نفسه.
- **بلا إضافة ملفات نظام**. لا يصل التطبيق إلى القرص إلا عبر أوامره الستة
  الخاصة، وكل واحد يعمل شيئًا واحدًا.
- إذن الحوار هو الوحيد الممنوح زيادةً على `core:default`.
- نطاق بروتوكول الأصول `**`، وهو واسع عن قصد: مشغّل وسائط يجب أن يفتح ملفًا
  من أي مكان يشير إليه المستخدم، بما في ذلك قرص USB. يقرأ ملفات اختارها
  المستخدم أصلًا، ولا يوجد مسار شيفرة يقرأ غير ذلك.

معرّف الحزمة هو `com.almenber.custommediaplayer`، موافقًا لمسار المشروع. وهو
يصبح اسم الملف التنفيذي على ويندوز، فإذا أردت غيره فهو سطر واحد في
`tauri.conf.json` قبل أن تبني للعميل.

## ٧. الاختبارات

```bash
npm test                                        # ١٤٤ اختبار وحدة، بلا شاشة
cargo test --manifest-path src-tauri/Cargo.toml # ٦ اختبارات Rust، بلا شاشة
npm run test:e2e                                # ٥ مجموعات متصفح، نسخة الويب
```

اختبارات سطح المكتب لا تفتح نافذة عن قصد. كل ما يمكن فحصه مقابل هيكل وهمي أو
مجلد مؤقّت يُفعل، فتشغيل التطبيق على شاشة لا يلزم إلا للأشياء التي تتطلّب واحدة
فعلًا.

## ٨. ملاحظات لبناء ويندوز

لم يُشغَّل أي شيء هنا على ويندوز، فهذه أول ما يُفحص:

1. `npm install` ثم `npm run desktop:build` على آلة فيها أدوات بناء MSVC
   ووقت تشغيل WebView2. وقت تشغيل WebView2 موجود افتراضيًا في ويندوز 11
   وفي ويندوز 10 الحالي.
2. مسار فيه مسافة، ومسار في `C:\Users\<name>\Videos` — المحوّل يقسم على
   الفاصلين معًا، وقد اختُبر بهما.
3. إعادة تشغيل: أضف ملفات، أغلق، افتح، تأكّد أن القائمة هناك.
4. اسحب ملفًا من مستكشف ويندوز إلى النافذة.
5. ‎`--diagnose` ينبغي أن يبلّغ `active_source: desktop` و`h264_playback: WORKS`.

مثبِّت `.msi` ومثبِّت NSIS مُهيّآن معًا. وNSIS على وضع التثبيت للمستخدم
ال الحالي، فلا يحتاج صلاحيات مدير.
